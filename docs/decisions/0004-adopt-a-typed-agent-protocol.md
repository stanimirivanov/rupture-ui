# ADR 0004: Adopt a typed agent protocol with Schema-decoded hypotheses

- Status: Accepted
- Date: 2026-09-24
- Milestone: M03 - Agentic proposals

## TL;DR

Agent hypotheses arrive as JSON over a request/response transport, decoded
through Effect Schema into a discriminated union of proposal kinds before
entering any atom. The reasoning chain is a linear array of typed steps.
Confidence is a number in `[0, 1]`. Blast radius is a set of service and
connection ids. Autonomy modes are a discriminated union of `suggest`,
`approve`, and `auto`. Tagged failures distinguish transport, decode,
authorization, conflict, timeout, and unexpected defects. The UI never
authorizes based on agent output; the server remains authoritative.

## Context

M03 introduces the first UI behavior that consumes data the application did
not author. M01 and M02 rendered local fixtures that were trusted by
construction. Agent output is different: it is generated by an LLM-backed
service, may be malformed, may reference services or connections that no
longer exist, may exceed the operator's authority, and may be adversarial.

ADR 0002 already commits the workspace to Effect for schema decoding of
untrusted payloads. `CONTRIBUTING.md` and `AGENTS.md` both require that
remote data is decoded before it enters atom state. What remains is the
shape of the payload, the taxonomy of failures, the transport, and the
authority boundary between the UI and the server.

The proposal's Phase 2 requires the UI to show a reasoning chain with a
confidence score and a blast-radius preview before any action is offered.
That is a design constraint, not an implementation detail, and the ADR
records it so it survives the first refactor of the hypothesis feed.

The three nozzle kinds from M02 (`latency`, `packet-drop`, `cpu`) are the
initial proposal kinds. New kinds extend the union; the UI branches
exhaustively.

## Decision

- **Transport for M03 is request/response, not streaming.** The mock server
  returns a complete list of hypotheses. Streaming reasoning is deferred;
  the schema is transport-neutral, so the change is a wrapper around the
  fetch, not a schema change.
- **Every hypothesis is a discriminated union on `kind`.** Initial kinds
  match the nozzle kinds from M02. Unknown kinds fail schema decoding
  rather than being silently ignored; a new kind is a deliberate schema
  change, not a runtime surprise.
- **Reasoning is a linear array of steps.** Each step has an `id`, a
  `text`, and an optional `evidence` reference. A tree or DAG is deferred
  until a slice needs it.
- **Confidence is a number in `[0, 1]`.** The UI displays it and never
  acts on it. The number is the model's claim, not an authority signal.
- **Blast radius is a set of service ids and connection ids.** The canvas
  highlights those services and connections. The set is a display signal.
  The server enforces the blast radius, not the UI.
- **Autonomy modes are a discriminated union of `suggest`, `approve`,
  `auto`.** The default is `approve`. `auto` is never the default and does
  not persist across sessions in M03. The dial UI is a later slice; the
  schema exists now so the fixture and the future wire format share one
  shape.
- **Tagged failures use the taxonomy from `docs/architecture.md`:**
  authentication, authorization, absence, conflict, invalid input,
  timeout, stream failure, invalid message, unexpected defect. Only a
  subset is reachable in M03; the schema declares the full set so the UI
  branches exhaustively from the first slice.
- **The UI never authorizes based on agent output.** A hypothesis may
  propose an action. The action is authorized server-side when the
  operator approves it, not by the presence of a hypothesis in the feed.
  This restates the engineering standard in the specific context of
  agentic UI.
- **Effect Schema is the decode layer.** Hypotheses are decoded from
  `unknown` at the fetch boundary; nothing downstream sees `unknown`.
  The decoder is the contract the mock server implements and the real
  engine must satisfy.
- **The M03 fixture is decoded through the same schema.** This is a
  deliberate change from M02, where the fixture was a plain typed
  constant. Agent payloads are the first data in the app that will come
  from an untrusted source; exercising the decoder from the first slice
  is a stronger test of the boundary than retrofitting it when the wire
  arrives. A malformed fixture fails the same way a malformed server
  response will.

## Consequences

The decode boundary is tested from the first slice. A malformed
hypothesis becomes a typed failure with a designed UI, not a runtime
crash. The failure UI and the success UI are built together because the
schema makes both reachable.

The schema is the wire contract. The mock server generates data the schema
accepts; the real engine must too. A schema change is a wire change, and
review must treat it that way.

The blast-radius set is display data. A code reviewer must be able to see
that the UI highlights but does not gate. If a future change makes the UI
responsible for enforcement, the ADR must be superseded, not amended.

The autonomy union exists in the schema before its dial exists. This is
deliberate: introducing it later would mean re-decoding existing fixtures
and re-reviewing the failure paths. The cost is a small amount of schema
surface without a UI consumer in the first slice.

Streaming reasoning is deferred. If the mock server shows that reasoning
needs to stream to feel responsive, the change is additive: the schema
stays, the fetch becomes an Effect Stream.

## Alternatives considered

- **Skip schema decoding for the fixture and add it with the wire.**
  Rejected: the fixture is the only thing in M03 that is easy to test,
  and a schema-decoded fixture is a stronger test of the decode path
  than a live mock server would be. Retrofitting a decoder is a larger
  change than writing it once.
- **Represent the reasoning as a free-form string.** Rejected: the
  proposal's Phase 2 requires step-by-step reasoning to be reviewable,
  and a string cannot be expanded to steps. The step array is the
  minimum that satisfies the requirement.
- **Represent blast radius as a description string.** Rejected: the
  canvas must highlight the affected services and connections, which
  requires ids. A description can accompany the id set but cannot
  replace it.
- **Confidence as a categorical level (`low`/`medium`/`high`).**
  Rejected for M03: the underlying model produces a probability, and
  collapsing it loses information the operator may want. If user testing
  shows the number is noise, M06 may revisit.
- **Autonomy mode in the URL.** Rejected: an autonomy mode in a shareable
  URL would allow a link to silently raise authority. The mode is session
  state, not navigation state.
- **Streaming reasoning in M03.** Rejected: no M03 slice needs it. The
  proposal's Phase 2 shows a chain; a chain arriving in one fetch is a
  chain.
- **Trusting the mock server and deferring the decoder.** Rejected: the
  decode path is exactly the path that will receive untrusted data. The
  first slice that consumes agent output is the correct place to establish
  the boundary.
